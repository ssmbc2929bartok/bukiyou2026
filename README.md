# bukiyou2026

「不器用ファクトリー」に提供する性格診断アプリ（要件定義書 BKF-001 第1.1版）。
ワークショップの待ち時間に、子どもが20問に答えると「性格タイプ」と「にている企業」が出る。回答は GAS でスプレッドシートに保存する。

HTML / CSS / JavaScript だけで動き、ビルドは要らない。GitHub Pages でそのまま公開できる。

## 画面と機能

| ID | 内容 | ファイル |
|---|---|---|
| S-001 トップ画面 | 背景は「スタジオあかり背景」 | `index.html` `#screen-top` |
| S-002 質問画面 | 年れい → 20問 → 気になる企業。デザインは hero-survey | `#screen-question` |
| S-003 回答確認画面 | 回答の一覧。タッチすると直せる | `#screen-confirm` |
| S-004 結果表示画面 | 性格タイプ・企業・選ばれた理由・企業の説明。背景は「スタジオあかり背景」 | `#screen-result` |
| S-005 未記入ポップアップ | 選ばずに「これに きめた！」を押したとき | `#popup-unanswered` |
| S-006 データ送信エラー | 送信に失敗したら再送し、それでも失敗したら保存せずに結果へ進む | `#popup-send-error` |
| F-001 診断機能 | 質問を出して回答を覚える | `js/app.js` |
| F-002 診断結果演算機能 | コサイン類似度で性格タイプ・企業を出す | `js/diagnosis.js` |
| F-003 データ集計機能 | スプレッドシートへ保存・集計（R-001） | `js/api.js` `gas/Code.gs` |

## ファイル構成

```

privacy.html          プライバシーポリシー（案）

js/data/axes.js       性格の12軸

js/data/types.js      性格タイプ（8種類）

js/app.js             画面の流れ

```

## 手元で動かす

`index.html` をブラウザで開けば動く。`js/config.js` の `gasUrl` が空のあいだはデータを送らない。

URL の最後に `?debug` を付けると、結果画面の下に回答者ベクトル・各企業との類似度・送信データが出る。

## 開催のたびに変えるところ（`js/config.js`）

- `eventId`：開催回の名前（例 `2026-10`）。スプレッドシートで回ごとに分けるのに使う
- `companyIds`：その回に参加する企業の id。空なら `js/data/companies.js` の全社
- `gasUrl`：GAS ウェブアプリの URL

参加企業が新しく増えたら、`js/data/companies.js` に1社分を足す。

## GAS（スプレッドシート）の準備

1. 保存用の Google スプレッドシートを作る（閲覧できる人は Google アカウントで限定する）
2. 「拡張機能 → Apps Script」を開き、`gas/Code.gs` の中身を貼って保存する
3. 関数 `setup` を選んで実行する。権限の確認が出たら許可する。シートが4つできる
4. 「デプロイ → 新しいデプロイ → 種類：ウェブアプリ」
   - 次のユーザーとして実行：自分
   - アクセスできるユーザー：全員
5. 表示された「ウェブアプリ URL」を `js/config.js` の `gasUrl` に貼る
6. エラーをメールで受け取るときは「プロジェクトの設定 → スクリプト プロパティ」に `ADMIN_EMAIL` を足す

`Code.gs` を直したときは「デプロイを管理 → 編集 → 新バージョン」で更新する（URL は変わらない）。

### できるシート（R-001）

| シート | 中身 |
|---|---|
| 回答 | 1回の診断が1行。`a_q01` などは選んだ選択肢（1始まり、0 は「どれでもない」）、`v_*` は回答者ベクトル、`s_*` は各企業との類似度 |
| 企業集計 | 開催回 × 企業ごとの「診断結果になった回数」「気になる企業に選ばれた回数」 |
| 回答集計 | 開催回 × 質問 × 選択肢ごとの回数。回答のばらつき・かたよりの確認用 |
| エラー | アプリで送信に失敗した記録 |

`interest`（気になる企業）は、ニューラルネットワークの教師あり学習の正解ラベルに使う。

## 判定のしくみ（F-002）

線形モデル + コサイン類似度。

1. 選択肢ごとに12軸の効果ベクトル `w` を決めておく（`js/data/questions.js`）
2. 回答者ベクトル `u` は、選んだ選択肢の `w` を足したもの。「どれでもない」は 0
3. `u` と各企業・各タイプのベクトルのコサイン類似度を出し、いちばん大きいものを結果にする
4. 「ここが にてるよ！」には、`u` と企業の両方でプラスに強い軸を3つまで出す

特定の結果ばかり出ないように、

- 選択肢のベクトルは質問ごとに平均を引く（どれを選んでも同じ成分は打ち消す）
- 企業・タイプのベクトルも、並べたもの同士の平均を引いてから比べる
- `u` が 0 のとき（全部「どれでもない」など）はランダムに決め、`fallback` に記録する
- 同点のときはランダム

軸・選択肢・企業のベクトルは、10月開催用に手で決めた仮の値。開催後に回答データと社長アンケートで見直す。

### かたよりの確認

```
node tools/simulate.js
```

ランダムに10万人分答えさせて、各企業・タイプが何%出るかと、どの企業・タイプにもなれる回答があるかを表示する。データを変えたら実行して確かめる。
