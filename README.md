# bukiyou2026

「不器用ファクトリー」に提供する性格診断アプリ（要件定義書 BKF-001 第1.1版）。
ワークショップの待ち時間に、子どもが10問の質問とミニゲームに答えると「性格タイプ」と「にている企業」が出る。
回答は GAS でスプレッドシートに保存する。

HTML / CSS / JavaScript だけで動き、ビルドは要らない。
GitHub Pages でそのまま公開できる（main に push すると `.github/workflows/pages.yml` で公開される）。

ミニゲームの仕様は [docs/games.md](docs/games.md) にまとめてある。

## バージョンと変更履歴

いまの版の番号は `js/config.js` の `appVersion`。
トップ画面と結果画面のいちばん下に小さく出る（例：v2.1.0）。
スプレッドシートの「回答」にも `appVersion` として残るので、どの版で遊ばれた記録かが分かる。

## ミニゲームと実験の条件

- 開始時にランダムで条件 A（ゲーム1つ、5問目のあと）か B（ゲーム3つ、3・6・9問目のあと）にする。
- 難易度は年れいで決める（初級 3〜5さい / 中級 6〜8さい・ひみつ / 上級 9さい以上）。
- 出すゲームは、その難易度で遊べるゲームからランダムに選ぶ。
- 不具合のあるゲームは `js/data/games.js` の `enabled` を `false` にすれば出なくなる。

| id | ゲーム | ちなみ先 |
|---|---|---|
| screw | ねじ締め | 大豊製作所 |
| crossword | クロスワード（中級・上級だけ） | 不器用ファクトリー |
| memory | 絵合わせ | 枚方市 |
| trace | なぞる線 | IFA住宅設計室 |
| paint | 塗り絵 | ダイコロ |
| cream | クリーム作り | 香椎化学工業 |
| heat | 温度キープ | 朝日熱処理工業 |
| circuit | 回路 | ノボル電機 |
| stone | 石割り | 大阪石材工業 |
| ball | ボール転がし（スマホの傾き。使えない端末では別のゲームに変わる） | サンエス工業 |
| robot | ブロック命令 | 大阪工業大学 |
| jump | 全員ジャンプ | 枚方信用金庫 |
| bounce | 跳ね返し | アクテック |

## 手元で動かす

`index.html` をブラウザで開けば動く。
`js/config.js` の `gasUrl` が空のあいだはデータを送らない。

URL の最後に `?debug` を付けると、結果画面の下に回答者ベクトル・ゲームの点数・各企業との類似度・送信データが出る。

ゲームを1つだけ試すときは `?debug&play=ゲームのid&tier=難易度(0〜2)` を付ける（例：`?debug&play=robot&tier=2`）。
データは送らない。
終わると、記録した値と軸への点数が出る。
`?debug` のときは、ボール転がしを傾きなしで ◀ ▶ ボタン（矢印キー）で試せる。

## 開催のたびに変えるところ（`js/config.js`）

- `eventId`：開催回の名前（例 `2026-10`）。
  スプレッドシートで回ごとに分けるのに使う
- `companyIds`：その回に結果として出す企業の id。
  空なら `js/data/companies.js` の全社
- `gasUrl`：GAS ウェブアプリの URL
- `gameConditions`：実験の条件（何問目のあとにゲームを入れるか）

## GAS（スプレッドシート）の準備

1. 保存用の Google スプレッドシートを作る（閲覧できる人は Google アカウントで限定する）
2. 「拡張機能 → Apps Script」を開き、`gas/Code.gs` の中身を貼って保存する
3. 関数 `setup` を選んで実行する。
   権限の確認が出たら許可する。
   シートが5つできる
4. 「デプロイ → 新しいデプロイ → 種類：ウェブアプリ」
   - 次のユーザーとして実行：自分
   - アクセスできるユーザー：**全員**（来場者の端末はログインしていないため）
     大学の Google アカウントでは「全員」が選べないことがある
5. 表示された「ウェブアプリ URL」を `js/config.js` の `gasUrl` に貼る
6. エラーをメールで受け取るときは「プロジェクトの設定 → スクリプト プロパティ」に `ADMIN_EMAIL` を足す

`Code.gs` を直したときは「デプロイを管理 → 編集 → 新バージョン」で更新する（URL は変わらない）。
前の版で作ったシートには、足りない見出しが自動で足される。

### できるシート（R-001）

| シート | 中身 |
|---|---|
| 回答 | 1回の診断が1行。<br>`a_q01` などは選んだ選択肢（1始まり、0 は「どれでもない」）。<br>`v_*` は回答者ベクトル、`s_*` は各企業との類似度。<br>`condition`・`tier`・`games` は実験の条件・難易度・出たゲーム。<br>`g_<ゲームid>_<値>` はゲームの生の値 |
| 企業集計 | 開催回 × 企業ごとの「診断結果になった回数」「気になる企業に選ばれた回数」「ページを開いた回数」 |
| 回答集計 | 開催回 × 質問 × 選択肢ごとの回数。<br>年れい・条件・ゲームの回数も数える。<br>回答のばらつき・かたよりの確認用 |
| リンク | 結果画面の「もっと見る」を押した記録 |
| エラー | アプリで送信に失敗した記録 |

`interest`（気になる企業）と「もっと見る」を押した企業は、ニューラルネットワークの教師あり学習の正解ラベルに使える。

## 判定のしくみ（F-002）

線形モデル + コサイン類似度。

1. 選択肢ごとに12軸の効果ベクトル `w` を決めておく（`js/data/questions.js`）
2. ミニゲームの値は、同じ難易度の“ふつう”の値との差を −1〜+1 にして、決めた軸に最大 ±2 で足す（`js/data/games.js`）
3. 回答者ベクトル `u` は、選んだ選択肢の `w` とゲームの点数を足したもの。
   「どれでもない」と「とばした」ゲームは 0
4. `u` と各企業・各タイプのベクトルのコサイン類似度を出し、いちばん大きいものを結果にする
5. 「ここが にてるよ！」には、`u` と企業の両方でプラスに強い軸を3つまで出す

特定の結果ばかり出ないように、

- 選択肢のベクトルは質問ごとに平均を引く（どれを選んでも同じ成分は打ち消す）
- 企業・タイプのベクトルも、並べたもの同士の平均を引いてから比べる
- `u` が 0 のとき（全部「どれでもない」など）はランダムに決め、`fallback` に記録する
- 同点のときはランダム

軸・選択肢・企業のベクトル、ゲームの“ふつう”の値は、10月開催用に手で決めた仮の値。
開催後に回答データと社長アンケートで見直す。

### かたよりの確認

```
node tools/simulate.js
```

条件 A・B それぞれでランダムに10万人分答えさせて、各企業・タイプが何%出るかと、どの企業・タイプにもなれる回答があるかを表示する。
データを変えたら実行して確かめる。

### 回路の問題を作り直す

```
node tools/gen-circuit.js > js/data/circuit.js
```

## 公開前に確認すること

- 企業の説明（`js/data/companies.js`）は、トレーディングカードのページと 2023年のチラシを元にした。
  各社・事務局に確認する
- 選択肢の文言と効果ベクトル、ゲームの“ふつう”の値は仮。
  チームで見直す
- 絵合わせのカードは、いらすとやの画像を `assets/img/memory/` に置いて `js/data/memory.js` の `img` に書く。
  それまでは絵文字で出る
- `privacy.html` の保存期間・問い合わせ先を埋める
- `gasUrl` に、ログインなしで受け付ける（アクセスできるユーザー：全員）GAS の URL を入れる
